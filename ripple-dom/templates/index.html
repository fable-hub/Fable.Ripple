Templates

Html.template renders a list, like Html.each. It takes the same three arguments: the items, as a signal or as a function returning an array, a function giving an item's key, and a render function that builds the element for one item. An item that keeps its key keeps its element.

The difference is how the elements are built. Html.each calls the render function for every item. Html.template calls it once, keeps the element it returns as a model, and gives every item a copy of that model. Copying a DOM element is much cheaper than building one, so a table with thousands of rows appears faster.

Because the render function runs once, it does not receive an item. It receives a Signal whose value is the item of whichever row is being built or updated at the time, and the rules below follow from that.

Reading the item

item.Value returns the item of the current row. It works inside a binding: a function you pass to the DSL and that the library runs for each row, such as a reactive attribute, Html.text with a function, an event handler, attr.ref, Html.show or a nested Html.each. In the example above, every read of item.Value is inside one of those.

The render function runs once, before any row exists. A read of item.Value there throws an error, and the error says what to change.

The same applies to a signal taken from the item. Html.text item.Value.Label throws, because item.Value is read before the Label signal is passed on. Write Html.text (fun () -> item.Value.Label.Value).

Passing item itself is fine. Html.text item shows the item of each row.

A value that never changes is written the same way, with a function. A function that reads no signal runs once per row and is then dropped, so it costs nothing afterwards.

Rows that differ

Every row is a copy of the same model, so a row cannot have a different structure of its own. To change what a row contains depending on the item, use Html.show or Html.dynamic. Each row then builds its own branch, and rebuilds it when the item's signals change:

State per row

A Var created at the top level of the render function is created once, when the model is built, and shared by every row. With Html.each, each row gets its own. Keep the state of a row on the item instead, as Label is in the example above.

Code that runs later

Code that a binding schedules for later runs without it: a timer, a promise continuation, an observer callback. A read of item.Value from there throws the same error as a read at the top level.
