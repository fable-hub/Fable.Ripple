Equality and cutoff

Every signal compares its new value to its old one, and an equal value goes no further. The cutoff is a property of every source and every derived value, not something you opt into per call site - there is no memo to remember.

Propagation stops mid-graph

A dependency can change while the derived value does not. Everything downstream of the unchanged value stays untouched:

The writes to 2 and 4 recompute isEven, find it still true, and stop there - the effect does not run. Only 5 reaches it.

The cutoff, drawn

Three nodes in a line. parity maps a number to a word, and upper maps that word again:

Press +2: parity recomputes to the same string and the dot dies there - upper never runs. Press +1 and the change travels the whole chain.

Custom equality

The comparison is a parameter, on sources and derived values alike:

The default is structural. Signal.referenceEquals opts out of it, for large values where a structural compare costs more than a recompute:

The write recomputes sorted to [1; 2; 3] - structurally the same as before, but a freshly built list. Under the default comparison the effect would not rerun; under reference equality it does. That is the trade: no structural compare on every change, at the price of reacting to rebuilds that changed nothing.
