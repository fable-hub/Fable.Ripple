Lists

A form can hold a list of sub-forms: several addresses, several books, several line items. Each item is a record of Vars, the list itself is a Var of those records, and Form.list renders one sub-form per item.

Add a book, type in it, then remove the first one: the second keeps its text and its labels say #1.

The pieces

  • FormList.create names the list; withAdd and withDelete add the buttons, with their labels.
  • Items is your Var of items. The buttons write it; so can you.
  • Default builds the item the add button appends.
  • The item function gets the item and a context: FieldIdPrefix for the ids of its fields, Index for its position.

The result is the list of the item results; one failing item fails the form.

Your own list markup

Form.listWith is Form.list with a render function in front: you draw the list, the library keeps the items. The function receives the context and a config with the elements to place, an Add and a Disabled read; each element has its Items to render and a Delete.

withAutoFocus puts the cursor in the new guest's name as soon as it appears. The rows have a container of their own: Html.each adds new rows at the end of its parent, so a button placed after it in the same element would end up between the rows.

Sortable.list in the Plain package is a render function of the same kind, with a drag handle, up, down and remove buttons on each row.
