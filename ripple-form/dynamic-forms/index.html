Dynamic forms

Parts of a form can appear, disappear or change with what the user entered. Three combinators cover it.

A part that depends on a value

Form.andThen builds the rest of the form from the value of the first part. The function runs when that value changes, and the previous part is thrown away.

Pick Email, type an address, pick Phone, then Email again: the address is still there. The email field was rebuilt, but its value lives in the email Var, which was not.

The result of the whole form is the result of the part that is currently shown. A branch that needs several fields is a form of its own, built with Form.succeed and Form.append, and Form.section gives it a frame and a title.

A field that shows on a condition

Form.showIf takes a condition and a form. While the condition holds the form is there; otherwise it renders nothing, yields None, and cannot fail. The condition is a tracked read, so a Var read inside it drives it.

Tick the box: a required field appears. Untick it: the form is valid again. Tick it once more: the name you typed is back.

Disabling on a condition

Form.disableIf and Form.readOnlyIf keep the field visible and its value in the result, but the user cannot change it while the condition holds:

Which one to use

  • The shape of the rest of the form depends on a value: andThen.
  • One field or group comes and goes: showIf.
  • The field stays, the user just cannot edit it: disableIf.
