Two-way codecs

UrlCodec describes a route once and runs the description in both directions. The pipeline that parses a URL into a value also builds the URL back from it, so the links in your views and the parser in your router are the same code. Parse a URL, build it straight back, and you get the same string - the property the library's tests assert.

tryToPath builds without a leading slash; tryToHash prefixes #/.

Writing a codec

Two dialects, both finishing as a RouteCodec so they live in the same list:

  • Tuple is positional and terser. Use it for a route of one or two values.
  • Values names every value. Use it when the route carries a record, or more values than position can keep honest.

Either way the shape is the same: start at a path, add one step per value in URL order, then close with the union case.

Tuple

  1. Step 01

    Start the path

    Tuple.root matches no segment; Tuple.path "user" matches a literal one.

  2. Step 02

    Add one step per value

    In the order they appear in the URL.

    Tuple.string, Tuple.int and Tuple.custom each take a path segment. Tuple.fragment takes the # fragment. Tuple.Query.* mirrors every query combinator.

  3. Step 03

    Close it with the union case

    Tuple.ofCase Home for a case with no fields - it needs no prism, since recognising it is equality. Tuple.ofCase1 to Tuple.ofCase3 for one to three values, each taking a prism.

At this arity, position is easy to get wrong. Values names every value instead.

Values

Values starts from a curried constructor and gives every step a getter. Swapping two values of the same type is a compile error here, and a silent bug in Tuple.

  1. Step 01

    Start from the constructor

    Values.create takes a function building the payload from its values, one argument per step to come.

  2. Step 02

    Add one step per value

    Each with the getter that reads it back.

    Values.segment matches a literal segment. Values.string, Values.int and Values.Query.* each take a value and a getter, as in Values.int _.Width.

  3. Step 03

    Close it

    Values.asCase with the case's prism.

The parse side applies the constructor argument by argument, in pipeline order. The build side reads each value through its getter (_.Query), which is how it knows where in the record that value lives.

Prisms

Prism<'Route, 'Values> is a record of two functions, one per direction:

'Route is your route union. 'Values is what the case carries: one value for Tuple.ofCase1, a pair for Tuple.ofCase2, a triple for Tuple.ofCase3.

Embed builds a route from the values, so it is usually the case name on its own - Embed = User.

Project goes the other way, returning None when the route is a different case. That None is how building a URL fails over to the next codec in the list. A union with other cases therefore needs a | _ -> None branch; a single-case union is already covered by its one pattern.

The library does not derive prisms for you, so a union with five cases that carry values needs five of them. Keeping them in a Prisms module beside the route type is the convention the API's own documentation uses.
